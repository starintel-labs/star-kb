* Design and implementation
See [[file:../../../docs/operator-terminal.md][terminal commands and engine port]].
Canonical 0.10.1 ActorManifest exports supply compatibility; missing declarations
remain unknown. Prolog evaluates data-only compatibility. Structured investigate
goals and inspected single-step plans are client proposals. The engine alone owns
execution, policy and canonical results. The default adapter is unavailable; the
explicit test adapter is simulated and polling cannot manufacture progress. An
HTTP adapter consumes the separately owned goals interface, with explicit advance
and optional validated canonical evidence readback. Goal completion never implies
actor completion. Final landed-engine integration remains pending.

* Durable lessons
Canonical IDs can lexically overlap URLs/domains; imported IDs surface that
ambiguity. Existing actor exports mix legacy and canonical releases; do not infer
compatibility from actor names or silently relabel old manifests. Persist the
request ID before submit so a lost reply does not create duplicate work.
